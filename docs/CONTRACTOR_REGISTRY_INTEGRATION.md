# Проверка подрядчиков по официальным реестрам

## Цель

СтройВыбор хранит результат сверки подрядчика с официальными источниками отдельно от статуса верификации платформы. Внешний источник подтверждает конкретный факт (например, ИНН/ОГРН или наличие записи в реестре), но итоговое решение о статусе профиля принимает модератор СтройВыбора.

## Источники

Приоритетный источник для юридических лиц и ИП — официальные сведения ФНС России из ЕГРЮЛ/ЕГРИП и сервис «Прозрачный бизнес». Для автоматизированной интеграции ФНС предоставляет отдельный режим доступа к сведениям ЕГРЮЛ/ЕГРИП для использования в информационных системах; он требует оформления доступа и атрибутов подключения.

Дополнительные источники подключаются отдельными адаптерами: реестры СРО, лицензий и иные официальные государственные или отраслевые реестры.

## Модель данных

Таблица `contractor_registry_checks` хранит:

- подрядчика;
- источник;
- тип идентификатора;
- проверенное значение;
- статус `unverified | matched | mismatch | error`;
- нормализованный payload источника;
- дату проверки;
- модератора и комментарий.

История не перезаписывается. Новая сверка создаёт новую запись.

## Безопасность

1. Ответ внешнего сервиса никогда не переводит профиль в `verified` автоматически.
2. Если есть открытое совпадение по ИНН/ОГРН в `contractor_entity_matches`, подтверждение профиля блокируется.
3. Сырые ответы источников хранятся только в объёме, необходимом для подтверждения реквизитов; лишние персональные данные не должны сохраняться.
4. Секреты и атрибуты доступа ФНС/других провайдеров должны храниться только в server-side environment variables.
5. Ошибка или недоступность реестра не должна автоматически означать, что подрядчик недостоверен.

## Текущий режим

До получения официальных атрибутов интеграционного доступа модератор может выполнить проверку через официальный сервис и зафиксировать результат в карточке подрядчика. Это уже использует ту же таблицу и ту же историю, которую будет заполнять автоматический адаптер.

## Автоматический адаптер

После оформления доступа автоматический адаптер должен выполнять следующий контракт:

1. получить текущие ИНН/ОГРН компании;
2. запросить официальный источник;
3. нормализовать ключевые поля (статус, наименование, ИНН, ОГРН/ОГРНИП, дата регистрации, прекращение деятельности, признаки недостоверности, ОКВЭД — только когда источник их предоставляет);
4. сравнить с данными СтройВыбора;
5. создать `contractor_registry_checks` со статусом `matched`, `mismatch` или `error`;
6. при `mismatch` показать модератору расхождения и не подтверждать компанию автоматически;
7. записать действие в административный audit log.

Интеграция должна быть идемпотентной по идентификатору подрядчика, источнику и времени/версии выгрузки, чтобы повторная доставка одного ответа не создавала ложную историю.
